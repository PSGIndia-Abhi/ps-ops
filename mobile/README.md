# BestServe Mobile

A separate, native Android client for BestServe's field operations (technicians, supervisors, admins), built with React Native + TypeScript. It consumes the **existing** backend at [`/backend`](../backend) over its REST API — it does not wrap the web app, does not touch the database directly, and does not modify `/backend`, `/frontend`, `/frontend/android`, or `/infra`.

This app is Android-only by design (the `ios/` folder from the RN template was removed - see Architecture Decisions below).

## Prerequisites

- Node.js >= 20 (this project was built against v25.2.1)
- JDK 17+ (Android Studio ships one at `Android Studio/jbr`)
- Android SDK with **platform 36** and **build-tools 36.1.0** installed, `ANDROID_HOME` set
- The Android NDK (see "Known local-build gap" below if it's not installed yet)
- The backend running and reachable from your device/emulator (see `src/config/env.ts`)

## Setup

```sh
cd mobile
npm install
```

`android/local.properties` must contain `sdk.dir=<path to your Android SDK>` (gitignored — created per machine, not committed).

## Running

```sh
npm start          # Metro bundler
npm run android    # build + install debug APK on emulator/device
```

The Android emulator reaches your machine's backend via `10.0.2.2`, not `localhost` — `src/config/env.ts` already defaults to `http://10.0.2.2:3000` for debug builds. On a **physical device**, change that to your machine's LAN IP.

## Project structure

```
mobile/
  src/
    api/          # Centralized HTTP client + one module per backend domain (auth.ts today; jobs/visits/shifts/notifications land as those phases are built)
    auth/         # AuthContext (session state machine) + secure token storage
    components/   # Shared design-system primitives (Button, TextField, Banner, BrandMark, icons)
    config/       # Environment/base-URL configuration
    navigation/   # React Navigation stack + route types
    screens/      # One folder per flow (auth/, splash/, home/) — home/ is a temporary placeholder, see below
    theme/        # Color/spacing/typography/shadow tokens
    types/        # Shared TypeScript types mirroring actual backend response shapes
  android/        # Native Android project (generated by the RN CLI, then adjusted — see below)
```

`src/screens/home/HomePlaceholderScreen.tsx` is intentionally a placeholder, not a dashboard — it exists only to prove the authenticated session end-to-end. Phase 3+ replaces it with role-aware navigation (Admin/Supervisor/Technician).

## Architecture decisions worth knowing

- **State/data**: React Context (`AuthContext`) for session state; each screen owns its own local state. No Redux/MobX — not justified at this scope.
- **Networking**: a single Axios instance (`src/api/httpClient.ts`) attaches the bearer token and normalizes errors into one `ApiError` type; screens never call `axios`/`fetch` directly.
- **Secure storage**: `react-native-keychain` (Android Keystore-backed), not `AsyncStorage`, for the auth session.
- **Environment config**: `src/config/env.ts` switches on React Native's built-in `__DEV__` flag rather than pulling in `react-native-config`. This keeps the native surface smaller; swapping in a config library later is a one-file change if multiple build flavors are eventually needed.
- **Animation**: the launch/login intro animation uses React Native's built-in `Animated` API (native driver), not `react-native-reanimated` — it's enough for the fade/scale/translate sequence the launch experience needs, and avoids an extra native dependency.
- **Icons**: two hand-drawn SVG icons (`src/components/icons.tsx`, via `react-native-svg`) rather than a full icon-font library, since that's all Phase 1/2 needs.
- **`ios/` removed**: the RN CLI scaffolds an iOS project by default; it was deleted along with the `Gemfile`/CocoaPods scaffolding since this is an Android-only effort (per project brief) and an untouched, unbuilt iOS project would just be dead weight in the repo.
- **Nested git repo removed**: the RN CLI initializes its own `.git` inside `mobile/` by default; that was removed immediately so `mobile/` is tracked as normal files in this repository instead of behaving like a submodule.

## Known local-build gap (environment-specific, not a code issue)

This machine's Android SDK install does not currently include the **NDK** or Android **cmdline-tools** (`sdkmanager`). React Native 0.87's default Android build (New Architecture) compiles native C++ glue code via CMake, which needs the NDK even for a JS-only app with no custom native modules. Install the NDK via Android Studio → SDK Manager → SDK Tools → NDK (Side by side) to build locally on this machine; this does not require any project changes.

## Brand

Colors/spacing/typography in `src/theme/` are derived from the existing web app's real design tokens (`frontend/src/index.css`, `frontend/src/assets/auth.css`, `frontend/src/styles/job.css`), not invented. `src/components/BrandMark.tsx` documents why the launch mark is a redrawn vector rather than the existing 60×59px logo PNG — see the comment at the top of that file.
